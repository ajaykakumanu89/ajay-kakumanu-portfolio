# Portfolio content plan

## Audience and purpose

This portfolio is intended for senior technical-writing and developer-documentation roles, including AI and developer-tool companies. It should let a hiring manager read a useful writing sample, understand Ajay's contribution, and inspect evidence of technical verification.

The organizing message is: Ajay explains software clearly and improves the engineering processes that keep documentation accurate.

## First release

| Item | Purpose | Remaining work |
| --- | --- | --- |
| [Developer API guide](../samples/developer-api/README.md) | Demonstrate a complete, testable developer journey | Review with a reader unfamiliar with the demo |
| [Validator case study](../samples/documentation-validator/README.md) | Explain a documentation-quality problem and the automation approach | Confirm which career evidence may be shared and how the reported measurement was taken |
| [AI documentation brief](../samples/ai-assisted-documentation/README.md) | Plan an evidence-backed account of AI use and human verification | Perform the documented exercise and publish real observations |
| [Resume](../resume.md) | Provide complete professional context | Confirm preferred public wording before publication |

## Each project should answer

- Who is the audience and what task do they need to complete?
- What problem existed?
- What did Ajay personally write, build, verify, or coordinate?
- Why was the content organized this way?
- How was its accuracy checked?
- What changed for readers or the release process?
- What cannot be concluded from the available evidence?

Use the [sample template](sample-template.md) when adding another project.

## Future website structure

Home, Selected Work, About, Resume, and Contact are enough for an initial site. Give each project a direct link and make writing samples readable without a sign-in. Provide the source files where they help demonstrate the workflow.

The Git repository is the source of truth for this starter. A website framework and hosting provider have not been selected.

## Additional samples to consider

- A before-and-after UX writing example using original fictional interface text.
- A troubleshooting guide based on a public tool and a reproducible failure.
- A contribution to an open-source documentation project with a reviewable pull request.

Job requirements can change. Recheck the target role when tailoring an application.
